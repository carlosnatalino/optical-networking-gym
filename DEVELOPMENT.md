# Development guide

## Environment setup (uv)

```bash
uv venv --python 3.13 .venv
source .venv/bin/activate
uv pip install -e ".[dev]"
```

The `dev` extra installs `pytest`, `coverage`, `mypy`, `ruff`, `Cython`, and
`setuptools`.

## Building the Cython extensions

The hot paths are implemented as Cython kernels
(`src/optical_networking_gym/optical/kernels/*.pyx` and
`src/optical_networking_gym/runtime/_request_analysis_kernels.pyx`). Build them
in place with:

```bash
DEBUG=1 python setup.py build_ext --inplace
```

The generated `.c` files and compiled `.so` files are gitignored; they are
regenerated by `cythonize` on every build (Cython is part of
`build-system.requires`).

### Pure-Python kernel fallback

Each `.pyx` kernel in `optical/kernels/` has a `.py` twin with the same API.
When the compiled extension is not present, Python imports the `.py` module
instead, so the package works (more slowly) without a compiler. The
request-analysis kernel (`runtime/_request_analysis_kernels.pyx`) is guarded by
a `try`/`except ImportError` in `runtime/request_analysis.py`, which falls back
to equivalent pure-Python implementations in the same module. Because CI always
builds the extensions, the `.py` twins are excluded from coverage measurement
(see `[tool.coverage.run] omit` in `pyproject.toml`).

## Tests, lint, type check

```bash
python -m pytest -q            # test suite
ruff check .                   # lint (config in pyproject.toml)
mypy src                       # type check (config in pyproject.toml)
coverage run -m pytest && coverage report -m   # tests with coverage (fail_under=78)
```

One-shot build + test:

```bash
DEBUG=1 python setup.py build_ext --inplace && coverage run -m pytest && coverage report
```
